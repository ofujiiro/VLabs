# 0022. Distribution: a Windows installer, a Linux AppImage, generated notices, a user guide

- **Status:** accepted, November 2026 (extends decisions 0002, 0004 and 0005)

## The tasks

A person who is not a developer must be able to **install VLabs** on
Windows or Linux, **start it from the usual places** (Start menu, the
desktop's application list), **open songs by double-clicking them**,
**remove it cleanly**, and **learn it** without a developer's help. And
every copy that leaves the project must carry the licence notices its
outside code requires (decision 0005).

## Windows: an NSIS installer, per user

**Chosen: NSIS** (Nullsoft Scriptable Install System), zlib licence, a
small, long-lived tool that runs on Windows and on Linux (`makensis`), so
the installer script can even be checked on Linux.

- Installs for the current user, with no administrator rights, into
  `%LOCALAPPDATA%\Programs\<product>`: no security prompt, and updates
  never need an administrator.
- A Start menu entry, an optional desktop shortcut, the project file type
  (`.teto`) opening in VLabs, an entry in Settings › Apps with an
  uninstaller that removes the program but never the person's songs or
  settings.
- The installer script is generated by `cargo xtask installer` from the
  names in `daw-ident` (product name, program file name, file extension,
  application identifier) and the version, so renaming the product stays a
  one-line change (decision 0002).
- Not signed: a code-signing certificate costs money (the owner's call).
  Until then Windows SmartScreen warns on first start ("More info › Run
  anyway"); the user guide says so.

Rejected: **WiX** (MSI): it needs Windows to build, its licence is not one
decision 0005 lists, and recent versions ask organisations that earn money
with it to pay a maintenance fee. **Inno Setup**: fine technically, but its
licence is its own (not on decision 0005's list), so it would need the
owner's legal check; NSIS's zlib licence is on the list. An **installer of
our own**: too much risk for a one-off.

## Linux: an AppImage

One file that runs on most distributions without installing anything:
`cargo xtask appimage` assembles the AppDir (the program, a desktop entry
with the `.teto` file type, the icon, AppStream metadata, the licence, the
notices and the user guide) and packs it with `appimagetool` 1.9.1 (MIT),
downloaded by CI with its checksum checked.

- Built on Ubuntu 24.04 in CI, the oldest current LTS, so the AppImage
  runs on systems with glibc 2.39 or newer (newer builders would raise
  that bar). The program needs only `libasound.so.2` from the system
  (JACK, X11, Wayland and the graphics drivers are loaded when present).
- **Licence note for the owner:** every AppImage starts with the AppImage
  runtime, a small separate program (MIT) that mounts the bundled files.
  It contains statically linked libfuse (LGPL-2.1), musl, squashfuse, zstd
  and zlib. It is not linked with VLabs's code and does not change VLabs's
  licence or the dual licensing; the notices file names it and where its
  source is. This is the same situation as any AppImage; the owner should
  confirm it is acceptable (like the Unicode exception of decision 0005).

## Generated third-party notices

`cargo xtask notices` writes `THIRD_PARTY_NOTICES.txt` from the real
dependency graph (`cargo metadata`, for Linux and Windows): every crate
built into the program, with its version, licence, source and its own
licence and notice files (or the standard text, with its authors, for the
few crates that ship none). Identical texts (Apache-2.0, mostly) are
printed once. The bundled fonts and sounds come first, then the AppImage
runtime. `cargo xtask dist`, the installer and the AppImage include it,
and CI generates it on every change so a crate whose licence text cannot
be found fails early, not on release day.

## The user guide

`docs/user-guide.md`, in the same plain language as the program, with
screenshots: getting started (the first note in a minute), the screens,
patterns and the piano roll, the step grid, the song, recording notes and
sound, the mixer and effects, plugins, automation, the key and chords,
tempo and signatures, the synth, files (saving, recovery, importing and
exporting), keyboard shortcuts, and what to do when something does not
work. `cargo xtask dist` turns it into one self-contained HTML page (with
`pulldown-cmark`, MIT, a developer tool only) shipped next to the program;
the menu's "User guide" (F1) opens it in the browser, or the copy on the
project's website when it is not there (a build from source).

## The version

The workspace's version becomes 0.6.0, the phase 6 build (the convention
written in `Cargo.toml`: 0.N.0 ends phase N). 1.0.0 is the owner's call
once the hands-on checks of phases 3 to 6 are done.

## Consequences

- `build.yml` produces three downloads: the Windows installer, the Linux
  AppImage, and the plain release folders as before.
- The program writes its icon files when asked (`--write-icons <folder>`),
  so the installer, the desktop entry and the window share one drawing.
- What I could not check myself: the installer on a real Windows machine
  (CI builds it; `makensis` checks the script on Linux too), SmartScreen's
  warning, and the AppImage on distributions other than Ubuntu.
